## הבעיה

עסק קמעונאי קטן מאבד לידים כי אין מי שיחזור אליהם, עונה לאותן חמש שאלות עשר פעמים
ביום, ומפיק חשבוניות ידנית בסוף כל יום. שלוש עבודות שלמות שאף אחד לא רוצה לעשות.

## הפתרון

מערכת אחת שרצה ברקע ומטפלת בכל השלוש.

> **ליד נכנס** → נבדק מול המאגר → נשמר → הבעלים מקבל התראה
> **אחרי שעות ספורות** → סוכן AI כותב לו מייל אישי ושולח
> **כשהוא עונה** → המערכת מזהה ומעדכנת את הסטטוס לבד
> **הוא שואל שאלה בטלגרם** → סוכן שירות עונה מתוך מסמכי המדיניות והקטלוג
> **נוצרת חשבונית** → מע"מ מחושב, PDF ממותג מופק, נשמר בדרייב, הקישור חוזר לטבלה
> **הבעלים שואלת "מה ההכנסות?"** → סוכן המנהל עונה מהנתונים החיים

בלי אף לחיצה ידנית.

## ⚙️ האוטומציות

| | שם | טריגר | מה היא עושה |
|:--|:--|:--|:--|
| **WF0** | Error Handler | Error Trigger | מקבלת כשלים מכל האוטומציות ושולחת התראה מפורטת בטלגרם |
| **WF1** | Tax Doc Validation | Airtable Trigger | מזהה חשבונית חדשה, מחשבת מע"מ 18% וסך הכל, מעדכנת סטטוס |
| **WF2** | Lead Intake | Webhook | קולטת ליד חיצוני, מסננת כפילויות לפי אימייל, מתריעה לבעלים |
| **WF3** | Sales Cold Emails | כל 3 שעות | כותבת מייל מכירות אישי ב-LLM ושולחת לליד בסטטוס New |
| **WF4** | Sales Reply Check | כל 30 דקות | סורקת את תיבת הדואר, מזהה מענה מליד, מעדכנת ל-Replied |
| **WF5** | Customer Service Agent | Telegram | סוכן שירות עם RAG על המדיניות ועל הקטלוג |
| **WF6** | Policies Embedding | Form | טוען את מסמכי המדיניות למאגר `mypolicies` |

## 🧠 RAG

שני מאגרים וקטוריים, embeddings של `text-embedding-3-small`:

**`mypolicies`** — 12 מסמכי מדיניות: החזרות, אחריות, משלוחים, תמחור, תשלומים,
כללי חשבונית מס בישראל, גבולות הסוכן, טון שירות, פלייבוק מכירות, תדריך מנהל,
סקירת העסק ושאלות נפוצות. מפוצלים ל-**78 מקטעים** באמצעות Recursive Character
Text Splitter.

**`theproducts`** — קטלוג 34 המוצרים.

> ⚠️ המאגרים בזיכרון. אחרי הפעלה מחדש של n8n יש להריץ שוב את WF6 ו-WF7.

## 🛡️ טיפול בשגיאות — שתי שכבות

**ברמת הצומת** — בכל אוטומציה, צמתים קריטיים מוגדרים `Continue (using error
output)` עם ניסיון חוזר, ומנותבים לענף Error ייעודי. כשלון נקודתי לא מפיל את
הזרימה כולה.

**ברמת האוטומציה** — WF0 מוגדר כ-Error Workflow בכל אחת מהאוטומציות. כשהרצת
production נכשלת, n8n מפעיל אותו אוטומטית והוא שולח לטלגרם את שם האוטומציה, הצומת
שנכשל, הודעת השגיאה המקורית וקישור ישיר להרצה.
